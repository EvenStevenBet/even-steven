# v1.11 / v1.6 Mainnet Deploy Plan — DRAFT, not signed off

**Status: awaiting explicit sign-off from Jeff. No mainnet transaction has been sent.**

This plan covers deploying **MarketDeployer v1.1**, **SportsbookFactory v1.6** and the
**SportsbookMarket v1.11** bytecode they carry. It is the Even Steven **v3** release:
relayed claiming, a second bet entry point for smart-contract wallets, two additive events,
two custom errors replacing OpenZeppelin require-strings, and the optimizer moved from
`runs=1` to `runs=200`.

Unlike the v1.10 deploy, this one is **not** unblocking anything that is currently broken.
v1.10/v1.5 is live and healthy. v3 is an additive upgrade, so the bar for cutting over is
"nothing regresses", and the cutover question below is the real decision, not the deploy.

## Pre-flight: compiler settings

**The optimizer runs value changes in this release.** Every previous plan says `runs=1`.
This one is `runs=200`, decided from the Stage 3 gas table. Re-check every row **every
time**, including mid-session.

| Check | Correct value | What happens if wrong |
|---|---|---|
| Compiler version | `0.8.20+commit.a1b79de6` | Different bytecode than what was measured and audited. A stray toolchain can silently substitute another 0.8.x — this happened during the v2 build and invalidated a full round of size measurements. Confirm the exact commit hash, not just "0.8.20". |
| Optimizer | **Enabled** | Off → deployment fails outright |
| Optimizer runs | **200** — *not 1* | Every size in this document is measured at 200. At runs=1 the market is 18,022 instead of 18,270, so a size check against this table would fail and you would be deploying an unaudited build. |
| **EVM Version** | **`shanghai`** — not `paris`, not default | `paris` adds ~450 bytes. Unchanged from v1.10. |
| MetaMask network | **Base** (mainnet, chain ID 8453) | Remix's provider dropdown can silently default to a different chain after any refresh — this happened twice during the v1.9 deploy. Re-check MetaMask's indicator *and* Remix's Deploy-panel badge before every Deploy click. |
| Remix provider dropdown | Plain **"MetaMask"**, not a named chain | The named-chain list may not include Base; plain "MetaMask" follows whatever network the extension is actually on. |
| Value field on every write call | **0 wei** (nothing here is payable) | A stray nonzero value makes an otherwise-correct call revert. |

### Expected compiled sizes — verify before deploying

Measured at Gate 1c with the settings above. If Remix reports materially different numbers,
**stop**: the compiler settings are wrong.

| Contract | Runtime bytes | Creation bytes | Headroom under 24,576 |
|---|---|---|---|
| `MarketDeployer` | **19,668** | 19,697 | 4,908 |
| `SportsbookFactory` | **8,085** | 8,585 | 16,491 |
| `SportsbookMarket` | **18,270** | 19,190 | 6,306 |

No EIP-170 size warning should appear on any of the three. For reference at `runs=1` the
same build is 19,439 / 8,048 / 18,022 — if you see *those* numbers, the runs setting is wrong.

The deployer is the tightest at 4,908 bytes of headroom, because it carries the market's
creation code. That is the number to watch in any future release.

## Deployment sequence

**Order matters.** The factory pins the deployer as an `immutable` at construction, so the
deployer must exist first and cannot be changed afterwards.

1. **Compile** `SportsbookMarket-v1_11.sol`, `MarketDeployer-v1_1.sol` and
   `SportsbookFactory-v1_6.sol` with the settings above. Confirm the three sizes.

2. **Deploy `MarketDeployer`** — no constructor arguments. Record the address.

3. **Deploy `SportsbookFactory`** with:
   - `_usdc` = `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`
   - `_oo` = `0x2aBf1Bd76655de80eDB3086114315Eec75AF500c`
   - `_deployer` = the MarketDeployer address from step 2

4. **Verify the wiring before anything else.** Call `factory.deployer()` and confirm it
   returns exactly the step-2 address. A factory pointed at the wrong deployer would mint
   markets running arbitrary code.

5. **Confirm `factory.settlementIdentifier()`** returns `ASSERT_TRUTH2`, and that the
   identifier is still whitelisted on Base mainnet. **Never** call
   `setSettlementIdentifier` on mainnet — that call is Sepolia-only, where `ASSERT_TRUTH2`
   is not whitelisted and `ASSERT_TRUTH` is.

6. **Approve USDC** for the factory from the production wallet: `type(uint256).max`
   (Circle USDC on Base rejects exact-amount approvals intermittently).

7. **Create one small test market** with the launch seed:
   `createMarket("<gameId>", <oracleZ>, 1000000)`. Confirm `MarketCreated` decodes with the
   same topic0 as v1.5/v1.4
   (`0xb0986a0038b9a2afc3b9dc7e400ddeb31ff547737cf738390752e5e6eba767a5`).

8. **Smoke-test on mainnet with small real amounts**, all four paths that are new or
   changed:
   - one `placeBet`;
   - one `placeBetFor` submitted from a *different* address than the signer — confirm from
     the decoded `BetPlaced` that `bettor` is the signer and the relay's USDC is unchanged;
   - one `claimPayoutFor` submitted by a relay for a bettor holding **zero ETH** — confirm
     `PayoutClaimed.bettor` is the bettor, the relay's USDC delta is 0, and one `BetClaimed`
     is emitted per claimed bet;
   - confirm `SettlementDetails` appears exactly once at settlement, immediately before
     `MarketSettled`, and that reconstructing the payout from logs alone matches what was
     received.

9. **Verify all three contracts on BaseScan** (Exact Match) using
   `scripts/verification/v1.11/standard-json-input.json`, which is already generated at
   runs=200 and checked to reproduce 19,668 / 8,085 / 18,270.

10. **Verify all three on BaseScan**, then cut over. Because no market is open under v1.5
    (verified above), the cutover is a straight swap with nothing to reconcile:
    `NEXT_PUBLIC_FACTORY_ADDRESS` in Vercel → the v1.6 address → redeploy.

11. **Update the bot `.env`** to the v1.6 factory address — after the deploy, and **before
    the bot opens any new market**. No bot code change: `createMarket`'s signature is
    unchanged. Confirm the bot's next market appears under `factory.getAllMarkets()` on
    v1.6 and not v1.5.

## Cutover decisions — DECIDED

All four are settled. Nothing in this section is open.

**1. Cutover timing: NOW. Clean cutover, nothing to reconcile.** Verified on chain against
the live Factory v1.5 (`0xf69d4c98…adbd`) rather than assumed:

```
  getMarketCount()      : 1
  getOpenMarkets()      : 0   []
  getUnsettledMarkets() : 0   []
  0x05170a958B4a1F70Fd8c6495F650475bCcbE43e9
      {"gameId":"NFL-2026-09-17-HOME-Bills-AWAY-Lions","bettingOpen":false,"settled":true,
       "canceled":false,"totalPool":"7.00"}
```

The single market ever created by v1.5 is settled and closed. Its three winning bets are all
claimed; the one unclaimed bet (id 1, 2 USDC, LESS at `lockedZ 34657` against
`finalSpread 10`) is a **loser owed nothing**, so it will never be claimed. The market holds
0.000002 USDC — two base units of floor-division dust from three winners splitting 5 USDC,
owed to nobody.

So the single-value `NEXT_PUBLIC_FACTORY_ADDRESS` problem does not arise: there is no market
that would disappear from `/api/markets/agent` or `/api/bet/quote` at cutover, and no
in-flight claim that needs the old factory to stay discoverable. Teaching the API to read
two factories is **not** needed for this release.

**2. Bot `.env`: updated as part of the deploy sequence** — after the mainnet deploy, and
**before the bot opens any new market**. The bot needs no code change, since `createMarket`'s
signature is unchanged between v1.5 and v1.6. This is now step 11 below.

**3. Stale references: cleaned.** Grepped the whole workspace for every superseded factory
address rather than working from a list. Fixed in this repo:

`index.html` was not on the original list and is the more serious of the two: the public

Historical references in `README.md`, `AGENTS.md`, `audits/` and the v1.9/v1.10 plans are

## Rollback / abort conditions

Stop and do not proceed if any of these is true:

- Remix reports a size other than 19,668 / 8,085 / 18,270, or any EIP-170 warning.
- `factory.deployer()` does not return the deployer deployed in step 2.
- `factory.settlementIdentifier()` is not `ASSERT_TRUTH2`, or the identifier is no longer
  whitelisted on Base mainnet.
- `MarketCreated`'s topic0 differs from `0xb0986a00…67a5`.
- The mainnet `claimPayoutFor` smoke test pays anyone other than the bet's recorded bettor.

Rollback is cheap for this release: v1.5 stays live and keeps working, and nothing points at
v1.6 until the cutover in step 10. An aborted deploy costs gas and nothing else.
